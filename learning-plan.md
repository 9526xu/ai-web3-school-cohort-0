# AI x Web3 School Learning Plan

Generated on 2026-05-18.

This plan follows the Handbook map: AI foundation, Web3 foundation, AI x Web3 bridge, and frontier project exploration.

## Success Criteria

- Maintain daily proof-of-work in `daily/`.
- Turn each learning task into one concrete artifact: notes, experiment, feedback, or submission record.
- Keep at least one Handbook feedback item whenever a page is unclear, outdated, or missing a practical example.
- By the hackathon phase, converge on one small demo with a repo, README, design note, and submission record.

## Week 1: Shared Language

Minimum path:

- Read Handbook home page.
- Read LLM, Prompt, Context, RAG, and Agent.
- Create one daily note per learning day.

Recommended path:

- Build a glossary of unfamiliar terms in daily notes.
- For each AI chapter, write one "what this means for Web3 systems" paragraph.
- Capture at least one Handbook feedback item if a chapter lacks examples.

Challenge path:

- Prototype a tiny agent workflow that reads a trusted context file and produces a cited answer.

## Week 2: Web3 Foundations

Minimum path:

- Read Network, Cryptography, Wallet, Smart Contract, and Account Abstraction.
- Summarize the difference between user wallet, smart account, session key, and agent permission.

Recommended path:

- Create a simple risk checklist for wallet-connected agents.
- Track questions that require mentor/community clarification.

Challenge path:

- Sketch an agent-wallet permission model with limits, revocation, and audit logs.

## Week 3: AI x Web3 Bridge

Minimum path:

- Read Chain-aware Context, Web3 Tool Use, Agent Workflow, Agent Wallet, and AI Security.
- Map one end-to-end workflow: user request -> context retrieval -> tool call -> human confirmation -> transaction/log.

Recommended path:

- Compare which steps can be automated and which require human-in-the-loop.
- Create at least one experiment under `experiments/`.

Challenge path:

- Build a minimal demo or simulation for tool calling, transaction preview, or permission checks.

## Week 4: Hackathon Direction

Minimum path:

- Choose one track: Agentic Commerce / Payment, Dev Tooling, AI Security / Privacy, AI x Governance / Coordination, or Open Track.
- Write `hackathon/project-brief.md`.

Recommended path:

- Define user, problem, trust boundary, demo path, and evaluation signal.
- Prepare a WCB/showcase-friendly README.

Challenge path:

- Ship a working demo with public repo, short video, and submission notes.

## Daily Cadence

Morning:

- Check WCB Learning page for today's course, task, meeting, and check-in entry.
- Pick minimum path, recommended path, or challenge path.
- Create or update `daily/YYYY-MM-DD.md`.

Evening:

- Record what was learned, what was built, blockers, and next actions.
- Draft check-in text.
- Manually submit to WCB/check-in platform.
- Save submission link or screenshot note in the daily file.
